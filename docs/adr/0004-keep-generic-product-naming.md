# ADR-0004: Product 네이밍 유지 및 멀티버티컬 확장 전략

## Status
Accepted

## Context
TicketSpring은 콘서트 티켓팅 이커머스로 시작하지만, 향후 야놀자·NOL과 유사한 범용 예약 플랫폼(숙소, 항공 등)으로 피벗할 계획이 있다.

**질문 1**: 콘서트 티켓은 회차·공연장·러닝타임 같은 도메인 특유 속성을 가진 애그리거트라 범용 이커머스 용어인 `Product`보다 `Performance`(공연)가 더 명확하지 않은지 — 이름을 좁힐지 범용으로 유지할지.

**질문 2**: 피벗 계획이 확정이라면 `Product`를 지금부터 멀티버티컬 구조(공통 속성 + 버티컬별 확장 스키마)로 설계할지, 이름만 미리 정해두고 실제 구조는 나중에 바꿀지.

## Decision
- `Product` 네이밍을 그대로 유지한다. 콘서트 외에 숙소·항공 등 다른 상품 유형으로 확장할 계획이 이미 있으므로 범용 명칭이 더 적합하다.
- 다만 지금 당장 멀티버티컬 스키마를 설계하지는 않는다. 콘서트 전용 필드(회차, 아티스트 등)를 그대로 두되, "Product 코어(공통) vs 콘서트 확장(고유)"만 개념적으로 구분해둔다. 실제 스키마 분리는 피벗 시점에 진행한다 (YAGNI).

## Consequences
- `Product`라는 이름 자체는 피벗 이후에도 바뀌지 않는다.
- 이 네이밍 결정이 [ADR-0001](./0001-separate-provider-domain.md)(`Provider`)과 [ADR-0002](./0002-separate-inventory-domain.md)(`Inventory`)의 범용 네이밍에도 그대로 이어졌다 — 판매자·재고 개념도 콘서트 전용 용어(`Organizer`/`Seat`) 대신 범용 용어로 통일.
