# ADR-0003: Auth 도메인 분리 및 통합

## Status
Accepted

## Context
소셜 로그인(카카오/네이버 등 OAuth) 여부나 자체 로그인 여부는 아직 정해지지 않았다.

**질문 1**: 어느 방식이든 토큰 발급/세션 관리 로직을 회원 프로필 데이터(`User`)와 같은 애그리거트에 둘지 분리할지.

**질문 2**: [ADR-0001](./0001-separate-provider-domain.md)에서 `Provider`를 별도 도메인으로 분리하기로 하면서, `User`와 `Provider`의 인증을 하나의 `Auth` 도메인으로 통합할지, 실무에서 흔한 것처럼 보안상 별도 시스템으로 분리할지.

## Decision
- `Auth`를 `User`(회원 프로필)와 분리된 도메인으로 둔다. 인증 방식이 바뀌어도 회원 도메인이 흔들리지 않게 하기 위함.
- `User`와 `Provider`의 인증은 하나의 `Auth` 도메인에서 role로만 구분해 처리한다. 지금 단계에서 별도 인증 시스템 두 개를 운영하는 것은 과설계로 판단했다.

## Consequences
- 로그인 방식(자체/소셜) 변경이나 `Provider` 인증 추가 시 `User`/`Provider` 프로필 도메인에 영향이 없다.
- 나중에 보안 요구가 커지면(예: `Provider` 쪽에 더 엄격한 세션 정책 필요) 그때 `Auth`를 분리하는 것으로 재검토한다.
